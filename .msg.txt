fix(replay): a crashed writer must not make a journal unreadable

replay_engine.py measured 35% coverage, which is usually a sign the module is
untested rather than broken. Writing tests found four defects, three of which
lose data.

A process killed mid-write leaves a truncated final line. json.loads raised on
it, so one interrupted append made the entire journal unopenable — and a
journal is append-only, so the damage is always at the end and everything
before it was still good. An unparsable record is now skipped and counted in
skipped_lines, and a caller replaying a partial journal can see that it was
partial.

export_replay wrote a JSON array and load_journal read one object per line,
so no exported journal could ever be read back. It exported as evidence and
replayed as nothing. The loader now accepts both shapes.

filter_events and export_replay read _events directly, so a caller who had not
called load_journal — the obvious way to use them — silently got an empty
result. Every reader now goes through one accessor that loads on demand.

get_last_sequence returned -1 on an empty journal. The result is meant to be
fed back to replay_from_sequence, and -1 is below every real sequence, so the
caller replayed nothing with no way to tell why. It is 0 now.

replay_from_sequence had the same trap as the readers: asking "replay from
where I left off" is exactly the case where the journal has not been loaded,
and it returned zero events.

Each fix was removed in turn and confirmed to fail a test; all four are caught.

Separately, astra/agent/apply.py measured 40% for the same reason — its only
tests went through the CLI, which runs in a subprocess and is invisible to
coverage. test_agent_apply.py calls it directly, and the file's refusals are
most of what is worth pinning: a dirty review is not applied at all, an edit
whose file changed since the review is refused, and the first refusal stops
the run before the next write.

Coverage 88.0% -> 88.3%, 369 passed, no file at zero.
