feat(agent): the loop the README claimed and the tree did not have

The project said it returned "ranked, token-budgeted context packs ready to
hand to any AI coding agent", and contained no code an agent could be handed:
nothing called a model, nothing parsed a reply, nothing closed the loop. The
pack builder, the AST differ, the risk scorer and the write endpoint all
existed; nothing connected them.

astra/agent/loop.py is that connection, and it calls no model. The model is a
callable the caller supplies, which is why every case here runs without a
network and why the loop works with any provider.

    question -> pack -> model -> proposed edit -> parsed diff -> risk
             -> the caller decides whether to write

The safety property is the point, and it is enforced rather than documented:
the model never receives a way to write. It returns text, the edit is checked
against the real file, and applying it is a separate call.

Three things are refused before they can become a suggestion:
- an edit whose old_text is not verbatim in the file it names, because a
  model that paraphrases the code it was shown would otherwise rewrite a file
  from a paraphrase
- an edit whose result does not parse
- an edit that changes nothing

astra/agent/apply.py is the other half and is deliberately separate. It
refuses a proposal whose file changed since the review, so an edit anchored in
code that has since moved cannot be applied against a review that no longer
describes it. It stops at the first failure rather than continuing: three
edits where the second no longer matches has already left the repository in a
state nobody reviewed.

Reachable three ways: POST /api/agent/propose takes the model's reply and
returns the review; `astra propose` does the same and can --emit the proposal;
`astra apply` writes it.

Nothing here needs a provider account to test, which is the point — the
previously untested claim was the one about being ready for an agent.
